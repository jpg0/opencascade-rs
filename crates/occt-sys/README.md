# occt-sys

This crate exists as a means to access the OCCT source code via crates.io. It is focused on just the geometry kernel and interchange formats of OpenCascade, and not other parts such as visualization logic. The crate size limit was increased to hold this repo, as otherwise the C++ code exceeds the default limits for a crate hosted on crates.io.

The version of this crate matches the upstream version of the OpenCascade code it provides.

There are some directories that are excluded to reduce the crate size, such as those containing test data, documentation, or code related to visualizations using things like OpenGL. You can see the full list of exclusions in [Cargo.toml](./Cargo.toml).

The [patch directory](./patch) also contains some modifications which removes modules that are unrelated to the geometry kernel aspects of OpenCascade. It is assumed a user of this crate will use wgpu or some other Rust graphics API crate to draw geometry generated by OpenCascade.

## FreeType and text

The `builtin` build links the CPU-side text toolkits (`TKService` and `TKV3d`) so that `StdPrs_BRepFont` and `StdPrs_BRepTextBuilder` can turn a string into B-rep geometry, which is how a model gets filled glyph outlines and how those outlines get extruded into solids. All of that machinery is compiled out unless FreeType is present, and OCCT drops FreeType silently when it cannot find it, leaving glyph calls as stubs that return null shapes; the build therefore requires a FreeType source tree and refuses to configure without one:

```sh
OCCT_FREETYPE_DIR=/path/to/freetype cargo build --features builtin
```

FreeType is built from that checkout as a static library with zlib, bzip2, png, harfbuzz and brotli disabled, and installed beside OCCT under `target/`. The bridge in `opencascade-sys/include/text.hxx` exposes the resulting text builder to Rust with the font supplied as bytes rather than a path, so a font can be compiled into a binary.
